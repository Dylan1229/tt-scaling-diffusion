## User Goal

The user is studying test-time scaling for Wan long video generation. The main question is how to generate VBench-Long-length videos with Wan while mostly preserving the existing code structure.

The working hypothesis is:

- Wan training/sampling is most natural around short clips, roughly the existing 81-frame / 5-second chunk setting.
- VBench-Long default target is 30 seconds, which maps to 6 chunks of 81 frames in this project setup.
- A naive 30-second direct T2V generation is too static.
- Independent 5-second T2V chunks preserve local quality/motion but lose continuity.
- T2V first chunk + I2V continuation chunks improves continuity, but a single sampled chain is unreliable.
- Branching over I2V continuation seeds exposes multiple possible long-video futures; selecting the best path can beat independent chunk concat.

## Implemented / Explored

- Minimal long-video support was added while trying to preserve the current structure.
- Three competing generation methods were compared with VBench-Long:
  - Direct 481-frame / 30-second T2V.
  - Independent 81-frame T2V chunks concatenated into 30 seconds.
  - Chunk 0 T2V, chunks 1-5 generated by last-frame I2V chaining.
- A chunk-branch I2V search experiment was added:
  - First chunk is fixed.
  - Chunks 1-5 each branch with 2 seed choices.
  - This gives `2^5 = 32` complete paths per prompt/root seed.
  - Initial test: 2 prompts x 2 root seeds.
  - Full run: 15 prompts x 2 root seeds = 30 roots, 32 paths each, 960 videos total.
- GPUs 4-7 were used/available for generation and evaluation during previous runs.

## Key Result

Main reported comparison across all 15 prompts and root seeds 0/1:

| Setting | overall_mean | Delta vs independent |
|---|---:|---:|
| independent concat | 0.752206 | 0 |
| all-zero/default I2V path | 0.739504 | -0.012702 |
| random-path mean over 32 | 0.741002 | -0.011204 |
| best-of-32 path | 0.778274 | +0.026068 |

Interpretation:

- Without search, T2V + I2V does not beat independent concat on average.
- Default/random I2V chains are worse mainly because dynamic degree, aesthetic quality, and imaging quality drop.
- Search changes the conclusion: best-of-32 beats independent concat overall and wins on 24/30 prompt/root-seed cases.
- The gain appears to come from recovering dynamic degree and imaging quality while keeping the subject/background consistency advantages of I2V chaining.
- The current best-of-32 result is oracle-style because VBench-Long itself is used to choose the path. A practical next step is a cheaper proxy ranker/scoring rule.
